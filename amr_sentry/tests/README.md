Use the existing `odoo13-unit-test-mock` skill at `$HOME/.hermes/skills/odoo13-unit-test-mock` on this host, or set `SKILL` to the corresponding installed skill directory in another environment. A test-only Docker template is provided under the repository's root `tests/` directory (`tests/Dockerfile.pytest`, `tests/requirements-pytest.txt`, and `tests/Dockerfile.pytest.dockerignore`) for the supported Python 3.7.3 runtime, with pytest 7.4.4 and test dependencies pinned. Build and run commands are in `amr_sentry/docs/testing.md`. Its build context is allowlisted to the Dockerfile and requirements; mount the repository and the separately installed skill read-only when running. The runner installs its isolation guards and selects `tests/unit`. The upstream skill README specifies Python 3.8+; Python 3.7.3 is validated for this project's test suite, not asserted as general upstream compatibility. Network-disabled tests are not a security sandbox. Do not install test dependencies in production. Mocked offline tests do not prove ORM, database, or runtime behavior.

The canonical addon-owned test bodies live in `amr_sentry/tests/unit` and `amr_service_client/tests/unit`; their `test_U11_sentry_*` modules in `amr_service_client/tests` are compatibility adapters for AC selectors. Shared case helpers remain under `tests/addons13_27/support.py`, but no Sentry test, selector, or probe remains in that shared directory. The local ORM probe is at `amr_sentry/tests/orm_68_probe.py`. Generic recursive discovery rooted at `amr_sentry/tests` is not an offline entrypoint: it imports integration and requires Odoo. AC selectors remain supported. Do not discover adapter modules and the unit directory together: they expose the same cases. `ac_tests` remains outside Odoo native discovery and uses its strict individual entrypoints; see its README. The integration test is under `tests/integration`; the former `integration_tests.test_service_client_hook` import is retained as a compatibility alias.
