## Compatibility and route contract

After transfer, installations with only `amr_token` no longer expose `/oidc/token`; installation must include `amr_oidc`, which depends on `amr_token`. No dual-route compatibility mechanism is proposed. Other OIDC routes, including JWKS, introspection, profile, authorization, and discovery, are outside this transfer and must remain unchanged, assigned/deferred as specified for ADDONS13-38.

Delete disposable databases, synthetic clients, hashes, users, and configuration; stop isolated Odoo instances; securely discard credential-bearing traces and retain only redacted evidence, candidate SHA, runtime version, and case verdicts. Never modify production/shared systems. If bootstrap behavior fails or is unsafe, remove the module from external `server_wide_modules` / `--load` and restart; do not claim the malformed-form criterion passes.
