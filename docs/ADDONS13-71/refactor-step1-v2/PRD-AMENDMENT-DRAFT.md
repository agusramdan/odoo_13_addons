## Keputusan keselamatan dan kompatibilitas — belum diputus
**D1 positional / migrasi.** Checkpoint `call(self, raise_exception=True, **kw)`: `client.call('POST')` mengikat string ke `raise_exception`, bukan method; jika tidak ada stored method, secara statis dapat menjadi GET dan membuang payload. Ini berisiko tinggi dan belum diterima Owner. Pilih: (A) pertahankan binding positional lama sambil mengimplementasikan refaktor kwargs; (B) API keyword-only dengan penolakan semua legacy positional yang ambigu **sebelum provider dan network**, pesan/migrasi dan inventaris consumer termasuk eksternal; atau (C) pertahankan silent remapping checkpoint hanya bila Owner secara eksplisit menerima risiko dan mitigasi — **tidak direkomendasikan**. Tentukan `prepare_request_context` positional headers kelima, direct call sampai enam argumen, duplicate binding, positional audience model call kedelapan, wrappers, versi transisi serta komunikasi. C tidak boleh dianggap implisit dipilih oleh permintaan refaktor.

**D2 headers.** Setujui/ubah C02 termasuk `None→{}`, batas jenis falsy dan identity/mutasi, inventaris provider/normalizer custom serta mitigasi. Efeknya pada AU10 spesifik; penerimaan risiko provider strict URL/header P2 tidak otomatis menerima perbedaan input normalizer ini.

**D3 method kosong/outbound.** Pilih C03 GET untuk direct call dan/atau sender dengan cakupan, guard/mitigasi dan risiko outbound secara eksplisit; atau tentukan failure sebelum provider untuk jalur yang dipilih. Tetapkan nilai falsy apa yang dicakup, perilaku `raise_exception`, log on/off dan payload; cegah D1 menghasilkan POST→GET tanpa keputusan. Tidak ada klaim adanya kontrol egress.

**D4 reporting.** Pilih nilai sebelum atau sesudah provider, termasuk provider mengubah/menghapus method, fallback preparation/auth failure, success, transport dan HTTP error; putuskan dampak direct-call R4/U14, hook melempar, serta metadata pelaporan. Jangan mengasumsikan perubahan kebijakan Sentry.

**D5 factory.** Putuskan path omitted versus explicit `None` untuk masing-masing call/get/post/put/delete dan fallback; apakah asimetri delete disengaja. Tentukan forwarding `audience`, `url`, `raise_exception`, daftar key lain dan penolakan unknown sebelum efek eksternal; akses `url` melalui factory memperluas entry point dan bukan penerimaan otomatis risiko P2. Tentukan positional audience dan rencana migrasi bersama D1. Checkpoint adalah fakta, bukan otomatis kontrak yang disetujui.
