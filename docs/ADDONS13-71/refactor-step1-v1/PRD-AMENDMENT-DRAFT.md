# ADDONS13-71 — PRD amendment refaktor API — DRAFT

**Acceptance=false.** Ini alternatif untuk keputusan Owner, bukan deskripsi API yang sudah dipilih. Berlaku additive terhadap predecessor dan URL/header accepted hanya jika disetujui eksplisit; tidak mengubah penerimaan lama atau risiko yang sudah diterima. Untuk bukti sumber, hash, regresi konkret, dan batas lihat `ANALISIS.md`. Semua actual test NOT RUN.

## Tetap wajib tanpa keputusan baru
1. Pulihkan input aktual `headers` ke `endpoint.request_headers_default`, termasuk `None` vs `{}`; hasil falsy tetap omit pada seam provider, URL/params/audience mengikuti amendment accepted. Pertahankan header positional kelima pada `prepare_request_context` sebagai default kompatibilitas parent, kecuali D1 dipilih lain. Jangan mengubah implementasi auth provider/cache/SSRF policy secara implisit.
2. Pertahankan snapshot active_log, error hooks/exception, payload termasuk key `active_log`, attribution dan U01–U14; direct call/action tidak berubah kecuali perubahan yang Owner spesifik setujui.

## Keputusan material sebelum memilih oracle implementasi
- **D1 — positional/signature (rekomendasi: pertahankan)**: A. pertahankan semua binding parent pada `prepare_request_context(path,method,params,payload,headers)`, `ServiceClient.call(method,path,params,payload,headers,raise_exception,**kw)`, dan `ServiceClientModel.call(service,method,path,params,payload,headers,credential,audience)` termasuk keyword, error duplicate binding, serta default raise; tidak memetakan string method ke raise_exception. B. setujui breaking API: tetapkan signature persis, penolakan positional secara aman sebelum efek eksternal, konsumen terdampak, inventaris deployment, migrasi/komunikasi dan rollout; bentuk kandidat sekarang yang silently remap `call('POST')` tidak layak dianggap disetujui. Compatibility break bukan risiko URL/header yang telah diterima.
- **D2 — method kosong (rekomendasi: pertahankan perilaku parent)**: A. jika method per-call dan stored falsy, preparation gagal sebelum provider/transport seperti parent; dispatcher tetap melalui jalur error-nya. B. tetapkan default GET: method per-call truthy > stored truthy > GET, payload tidak dikirim untuk GET; berlaku pada direct call dan sender, perhatikan HTTP/outbound dan log berubah. Owner memilih cakupan, menyetujui risiko, menetapkan pembatasan dan review keamanan jika diperlukan; tidak menganggap allowlist sudah ada. D1 dan D2 harus mencegah silent POST→GET akibat binding.
- **D3 — nilai `method` reporting (rekomendasi: parent)**: A. direct `call` melaporkan method argumen per-call pada sukses dan error, termasuk None ketika hanya constructor method tersedia. B. tentukan apakah yang dilaporkan method sebelum atau sesudah provider, fallback saat prepare/auth gagal, saat provider mengubah/menghapus key, dan ketika transport/HTTP gagal; catat dampak observability dan provider custom. Bukan perubahan kebijakan Sentry tersirat.
- **D4 — factory perluasan (rekomendasi: parent)**: A. kembalikan path required serta explicit audience untuk model `call`, path required bagi get/post/put/delete, dan perilaku parent terhadap unknown keyword. B. tetapkan secara eksplisit method mana boleh path omitted, apa fallback-nya, apakah `url`/`raise_exception`/keyword lain boleh melalui factory, apakah unknown ditolak, serta audience positional dan keyword; evaluasi tujuan URL dan pengendalian error. Jika B, revisi daftar parameter yang diperbolehkan dan test migrasi sebelum coding; jangan menyimpulkan semua `**kw` aman. Penerimaan risiko URL override sebelumnya tidak mencakup ekspansi titik masuk factory secara otomatis.
