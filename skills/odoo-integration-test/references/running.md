# Running safely

Use an isolated Odoo 13 instance, dedicated PostgreSQL database and test-only credentials; disable outgoing email, jobs and other external integrations. Verify identity and backup policy with the owner before using any preexisting database. Module install/update can change data even if tests roll back. The runner requires `--ack-test-db`; this is an explicit assertion by the operator, not verification that a database is safe. It rejects common production-like names and enforces a conservative identifier, but names are not proof of safety. Never point it at production.

`--mode install` passes `-i`; `--mode update` passes `-u`; both select `/addon` with `--test-tags` and stop after initialization. This selects all matching addon tests, including existing tests; it does not restrict to a filesystem directory. Dependencies may be installed/updated. Review logs to ensure intended classes and methods ran; zero collected tests may still yield success. The runner returns the Odoo process status, not a verified test count. Use the real Odoo command and environment rather than stock pytest. Do not pass conflicting `-d`, `-i`, `-u`, `--test-tags` or `--stop-after-init` in extra options; runner rejects them. Config files can still override or supply settings, so review them.

The bundled example requires Odoo 13, Python dependencies and PostgreSQL. Run it like any addon after adding the parent `examples/` directory to `--addons-path` along with Odoo's own addon directories. No database is created or destroyed by the helper.

Only after explicit authorization, a fully disposable local Docker setup can use an internal-only network, a fresh PostgreSQL container with its data directory on tmpfs, and read-only candidate/runner mounts. The official Odoo 13 image runs as UID/GID 101 (`odoo`); if `/var/lib/odoo` is tmpfs-mounted with a read-only root filesystem, set the tmpfs owner to `uid=101,gid=101,mode=0700`, or Odoo may fail at `/var/lib/odoo/filestore` before tests start. Verify logs contain `Ran N tests` and the expected test methods, not only exit 0. Record exact container/network IDs and verify their absence after cleanup; never broad-prune.
